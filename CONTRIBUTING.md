# Contributing

Keep `SKILL.md` as the single source of behavior. Adaptation documents may explain installation, but may not weaken its scope, risk, approval, or safety rules.

When changing behavior, update at least one relevant example and test case. Test the change in a fresh agent context with a realistic prompt. Review whether a designer can identify the user outcome, decision, risk control, and review path without reading code.

Do not add credentials, private data, vendor lock-in, network calls, or unsupported platform claims. Keep additions concise and platform-neutral unless they live in a clearly named adapter.
